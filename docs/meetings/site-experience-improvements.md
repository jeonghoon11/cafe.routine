# 사이트 경험 개선 회의

> 상태: 2차 회의 결정 완료

## 참여 및 범위

- 참여: FE, PM, PD
- 제외: BE
- 주제: Hero 영상 로딩, 영업시간 라이팅, 디카페인 안내 배치

## 결정 사항과 근거

### Hero 영상

- 현재 영상은 42초, 39,173,802B(37.36MiB)의 1280×720 H.264 파일이며 AAC
  오디오를 포함하고 총 비트레이트는 7.456Mbps다. fast-start는 이미 적용돼
  있다.
- `preload="none"` 상태에서 hydration 이후 `IntersectionObserver`가 `play()`를
  호출한다. Next.js의 정적 렌더링·ISR과 MP4 전송은 별개이므로 페이지가
  정적이어도 영상 용량과 네트워크 속도가 재생 시작 시간에 영향을 준다.
- 운영 환경의 첫 1MiB range 요청은 206으로 정상 응답하지만 TTFB가 약
  0.8~1.1초, 총 응답이 2.1~2.6초이며 전송 속도는 3.3~3.9Mbps로 영상
  비트레이트보다 낮다.
- 기존 파일은 `레거시2_routine-opening.mp4`로 보존하고, 원본 경로의 파일을
  정확히 0~8초의 무음 영상으로 교체한다. H.264 720p, 24/30fps로 내보내며
  최대 4MB를 목표로 한다.
- 기존 observer와 `preload="none"`은 유지한다. 압축 후에도 검은 화면 체류가
  문제일 때만 fade 또는 preload 변경을 후속 검토한다.

### 영업시간 라이팅

- 모든 요일의 시간이 같으면 `EVERY DAY`와 `11:00–22:00`을 표시한다.
  `Everyday`는 영업일을 뜻하는 표현으로 사용하지 않는다. FE·PM·PD 모두
  현재 브랜드의 대문자 영문 표기와 정보 명확성에 맞는 `EVERY DAY`에
  합의했다.
- 요일별 시간이 달라지면 기존 한국어 요일별 표기로 복귀한다. 브랜드 톤보다
  운영 정보의 명확성을 우선한다.

### 디카페인 안내

- Good Morning의 모든 메뉴가 디카페인 변경 대상임을 확인했다.
- `디카페인 변경 +1,000원`을 Good Morning 카테고리 안에 한 번 표시한다.
  데스크톱은 sticky category rail의 `ITEMS` 아래, 모바일은 제목·개수와 첫
  카드 사이에 배치한다.
- 페이지 하단에는 `메뉴와 가격은 매장 상황에 따라 달라질 수 있습니다.`라는
  일반 변동 안내만 유지한다.

## 구현 및 검증 계획

- FE: 기존 Hero 파일을 보존한 뒤 Swift와 AVFoundation의 설치 없는 export로
  0~8초 무음 영상을 생성하고 원본 경로에 적용한다.
- FE: 기존 observer와 `preload="none"`을 유지한 채 로컬 빌드와 운영 모바일
  환경에서 초기 재생, 반복 이음새, 용량을 검증한다.
- FE: 균일 영업시간의 `EVERY DAY` 표기와 불균일 영업시간의 한국어 요일
  fallback을 구현·검증한다.
- FE: Good Morning 카테고리에 디카페인 안내를 배치하고 페이지 하단에서는
  일반 가격 안내만 남긴다.
- PD: 데스크톱·모바일에서 Hero 문구 가독성, 반복감과 디카페인 안내의 정보
  위계를 검수한다.
- PM: 최종 문구와 적용 범위가 이번 결정과 일치하는지 확인한다.

## 완료 기준

- Hero 영상이 정확히 0~8초, 최대 4MB이며 오디오가 없고 눈에 띄는 끊김 없이
  반복된다. 기존 42초 파일은 `레거시2_routine-opening.mp4`로 보존된다.
- 운영 모바일 환경에서 영상의 첫 의미 있는 움직임이 1초대에 보이고 검은 화면
  체류가 유의미하게 줄어든다.
- 영업시간이 균일할 때 `EVERY DAY · 11:00–22:00`의 의미가 한눈에 전달되고,
  시간이 달라지면 한국어 요일별 표기가 정확히 노출된다.
- 디카페인 적용 범위가 매장 확인 내용과 일치하며, 데스크톱과 모바일에서 첫
  Good Morning 메뉴 카드 전에 안내를 발견할 수 있다.
- 일반 가격 변동 안내와 디카페인 추가 금액 안내가 서로 다른 범위로 인식된다.

## 영상 export fallback

- Swift와 AVFoundation preset 결과가 4MB를 초과하면 해당 결과를 적용하지
  않고 ffmpeg 설치 승인을 받은 뒤 H.264 720p, 24/30fps, 2~3Mbps 또는
  CRF 24~27로 다시 인코딩한다.
