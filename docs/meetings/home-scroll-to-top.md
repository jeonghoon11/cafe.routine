# 홈 상단 이동 버튼 회의

## 주제

긴 홈 화면에서 상단으로 돌아가기 어려운 문제를 줄이면서, ROUTINE의 핵심
행동과 브랜드 위계를 해치지 않는 상단 이동 버튼의 범위와 구현을 확정합니다.

## 참여 직군

PD, FE, PM

## 결정 사항과 근거

- 홈은 Hero, Invitation, 사진 8장, Explore로 이어져 상단 복귀 부담이 크므로
  상단 이동 버튼을 제공합니다. Menu와 Visit에는 적용하지 않습니다.
- 메뉴와 방문 정보 확인이 핵심 행동이고 상단 이동은 스크롤 이후에 필요한 보조
  행동이므로 SEED `ContextualFloatingButton`의 `layer`, `iconOnly` 조합과 위쪽
  화살표를 사용합니다.
- 버튼은 Hero가 화면 위로 완전히 벗어난 뒤 나타나고, Hero 영역으로 돌아오면
  숨깁니다. 임의의 스크롤 픽셀값 대신 Hero 경계를 관찰합니다.
- 동작 후 Hero 제목으로 focus를 옮겨 버튼이 숨겨질 때 focus가 유실되지 않게
  합니다. 모션 축소 설정에서는 부드러운 스크롤 대신 즉시 이동합니다.
- 우하단 위치는 오른쪽 `calc(16px + env(safe-area-inset-right))`, 아래
  `calc(24px + env(safe-area-inset-bottom))`로 정합니다. 문구 확장, 커스텀 장식,
  분석 이벤트, 새 의존성은 이번 범위에서 제외합니다.

## 담당자별 후속 작업

- FE: 홈 전용 컴포넌트 구현과 자동·브라우저 검증을 완료했습니다.
- PD: 최종 위치의 시각적 위계와 콘텐츠·CTA 가림 여부를 검수하고 승인했습니다.
- PM: 제품 범위와 3회 검증 기준 및 결과를 확인했습니다.

## 완료 기준

- 버튼은 Home에서만 렌더링되고 Menu와 Visit에는 나타나지 않습니다.
- 초기 화면과 Hero 구간에서는 숨겨지고, Hero가 화면 위로 완전히 벗어나면
  나타나며 상단 복귀 후 다시 숨겨집니다.
- 마우스 클릭과 키보드로 실행할 수 있고, 접근성 이름과 보이는 focus가
  제공되며 동작이 끝난 뒤 focus가 유실되지 않습니다.
- 모션 축소 설정에서는 즉시, 그 외에는 부드럽게 문서 상단으로 이동합니다.
- 모바일 safe area 계산식을 유지하고 `320px`, `390px`, 데스크톱에서 갤러리,
  Explore 링크, Footer 콘텐츠를 가리지 않습니다.
- 기존 Header, 주요 내비게이션, Hero의 Scroll 링크, Menu·Visit 링크 동작에
  회귀가 없습니다.
- `pnpm typecheck`와 `pnpm lint`를 통과합니다.

## 미결 질문

- 없습니다.

## 최종 승인과 검증 결과

1. 정적 검사: `pnpm typecheck`, `pnpm lint`, diff 검사를 통과했습니다.
2. 데스크톱: `1440×900`에서 오른쪽 `16px`, 아래 `24px` 위치와 콘텐츠를 가리지
   않음을 확인했습니다. `Enter`로 상단 이동 후 focus가 Hero 제목에 유지됐습니다.
3. 모바일: `390×844`에서 오른쪽 `16px`, 아래 `24px` 위치와 콘텐츠를 가리지
   않음을 확인했습니다. 클릭으로 상단 이동 후 focus가 Hero 제목에 유지됐습니다.

- 자동화 환경에서는 0이 아닌 safe area inset을 재현하지 않았으며, CSS 계산식에
  `env(safe-area-inset-right)`와 `env(safe-area-inset-bottom)`이 유지됨을 확인했습니다.
- PD는 브랜드 균형과 코너 고정감이 적절하고 콘텐츠·CTA를 가리지 않음을 확인해
  최종 승인했으며, safe area 계산식 유지를 권장했습니다. PM도 제품 범위와 검증
  결과를 확인해 최종 완료로 확정합니다.
