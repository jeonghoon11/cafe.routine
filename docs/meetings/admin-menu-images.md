# 관리자 메뉴 이미지 회의

## 주제와 참여

- 일자: 2026-10-13
- 참여: BE, FE. PM과 PD가 이미지 저장 시점과 표시 흐름을 검토했습니다.
- 사용자 요구: 메뉴 관리 목록에 이미지를 표시하고 추가·수정 화면에서 이미지를 등록하거나 제거합니다.

## 확인한 사실

- 메뉴는 `media_id`로 `media_assets`에 연결되어 있으며 공개 메뉴 페이지는 연결된 이미지의 public URL을 사용합니다.
- 기존 관리자 목록과 폼은 이미지를 조회·입력하지 않습니다. 기존 이미지 연결은 일반 메뉴 수정에서 유지됩니다.
- 이미지가 없는 공개 메뉴는 기존 fallback을 사용할 수 있습니다.

## 결정 사항과 근거

- 메뉴당 이미지 한 장을 관리합니다. 목록에는 썸네일, 이미지가 없으면 대체 표시를 제공합니다. 폼에는 현재 이미지 또는 선택한 파일의 미리보기와 선택·교체·제거 동작을 제공합니다.
- JPEG, PNG, WebP만 허용하며 파일 크기는 최대 1MB입니다. 요청 전체의 여유를 위해 Server Action 요청 제한은 2MB로 설정합니다. SVG 등 실행 가능하거나 지원하지 않는 형식은 받지 않습니다.
- 브라우저에서 파일을 decode해 미리보기와 크기를 확인합니다. 서버는 별도로 MIME, 파일 시작 바이트, 용량, 이미지 가로·세로 범위를 검증합니다. 파일 선택 UI의 제한을 서버 신뢰 경계로 사용하지 않습니다.
- 서버는 기존 관리자 인증·권한 검사를 수행하고 사용자 session과 Storage 및 테이블 RLS로 씁니다. 클라이언트에 관리자용 비밀 키를 제공하지 않습니다.
- 신규 파일은 `menu/{UUID}.{ext}` 경로로 저장하고 `upsert:false`를 사용합니다. 기존 파일을 덮어쓰지 않습니다. Storage 업로드 후 `media_assets`를 등록하고 메뉴의 `media_id`를 연결합니다.
- 이미지 유지·추가·교체·제거는 **메뉴 저장 버튼을 누를 때** 적용합니다. 파일 선택이나 제거를 미리보기한 뒤 취소하면 기존 메뉴 연결이 유지됩니다.
- 제거는 해당 메뉴의 `media_id` 연결을 해제합니다. 교체나 제거 시 기존 `media_assets` 행과 Storage 파일을 영구 삭제하지 않습니다. 다른 메뉴나 화면이 같은 자산을 사용하는 경우를 보호하기 위한 결정입니다.
- 저장 실패 시 이번 요청에서 새로 만든 이미지 행과 파일만 가능한 범위에서 정리합니다. 기존 파일과 자산은 정리 대상이 아닙니다. 실패한 요청의 정리 자체가 실패하면 새 파일이 남을 수 있으며 이 한계를 안내합니다.
- 이미지를 제거한 메뉴도 저장할 수 있고 공개 화면은 기존 fallback을 사용합니다.
- 공개 bucket의 이미지 URL은 공개 접근이 가능합니다. 메뉴의 **비공개** 상태는 공식 메뉴 목록에서 숨기는 기능이며 이미지 URL 자체의 접근을 차단하는 기능으로 설명하지 않습니다.

## 담당자별 후속 작업

- FE: 목록의 이미지 조회·썸네일·대체 표시, 폼의 파일 선택·decode·미리보기·제거, 저장 중 상태와 검증 오류 안내를 구현합니다.
- BE: 서버 검증, 관리자 권한과 RLS, 업로드·자산 등록·메뉴 연결 순서, 실패 시 신규 자산 정리 범위를 검토합니다.
- PD: 썸네일과 미리보기 크기, 이미지 없음 상태, 모바일 파일 선택과 삭제 피드백을 검토합니다.
- PM: 메뉴 저장 시 반영, 취소 시 보존, 공유 자산 보호와 비공개 의미를 확인합니다.

## 완료 기준과 검증 상태

- 기존 이미지가 관리자 목록과 수정 폼에 표시됩니다.
- 이미지 없는 메뉴의 추가·수정 및 이미지 추가·교체·제거가 가능합니다.
- 성공 저장 후 목록과 공개 메뉴에 새 이미지 또는 fallback이 반영됩니다.
- 취소·검증 실패·DB 저장 실패로 기존 이미지가 삭제되거나 기존 연결이 의도 없이 해제되지 않습니다.
- 잘못된 형식·용량·파일 내용과 비관리자 업로드 요청이 거부됩니다.
- 로컬 가상 E2E로 미리보기, 추가·교체·제거, 저장 실패와 재시도 흐름을 확인합니다.
- 구현 완료. 로컬 mock E2E에서 이미지 추가·교체·제거, 실패 입력 유지와 신규 자산 정리, 공개 이미지 표시를 통과했습니다. `pnpm typecheck`, `pnpm lint`, `pnpm build`, `git diff --check`를 통과했습니다. 운영 Storage 쓰기는 수행하지 않았습니다.

## 한계와 후속 확인

- 교체·제거된 기존 파일은 남습니다. 사용 여부를 확인하지 않고 지우지 않으며 자산 정리 도구는 이번 범위에 포함하지 않습니다.
- 신규 파일 정리 실패 시 잔여 자산이 생길 수 있습니다. 실제 운영 정리 정책이 필요해지면 별도로 합의합니다.
- 운영 Storage 관리자 policy와 public bucket 존재, media_assets insert grant를 읽기 전용 조회로 확인했습니다. 실제 운영 업로드는 수행하지 않았습니다.

## 운영 반영 확인

사용자 승인 후 migration 실행 성공을 확인했습니다. 읽기 전용 조회로 공개 정책의 AND 조건, 순서 RPC 등록·트리거 활성, 익명 실행 차단과 인증 사용자 실행 권한을 확인했습니다. 메뉴·Storage 쓰기 검증은 가상 환경에서만 수행했습니다.
