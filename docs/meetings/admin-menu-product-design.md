# 관리자 메뉴 제품·디자인 회의

## 주제

운영자가 공개 메뉴의 항목을 추가·수정·삭제하고 변경 결과를 확인하는 최소 관리자 흐름

## 참여 직군

PM, PD

## 일자

2026-10-13

## 참고 레퍼런스

- [Square: Create and edit items](https://squareup.com/help/us/en/article/8335-create-and-edit-items), [Shopify: Add or update products](https://help.shopify.com/en/manual/products/add-update-products): 목록에서 항목을 확인하고 상세 폼으로 추가·수정하는 CRUD 흐름을 참고합니다.
- [WCAG 2.2 Target Size (Minimum)](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum): 조작 대상의 최소 크기와 적용 예외를 검토합니다.
- [WAI-ARIA Alert Dialog](https://www.w3.org/WAI/ARIA/apg/patterns/alertdialog/), [WAI-ARIA Modal Dialog](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/): 삭제 확인을 맞춤 대화상자로 구현할 때 역할과 초점 이동·복귀 기준을 확인합니다.

## 사용자 문제와 목표

- 운영자는 공개 메뉴의 이름, 설명, 가격과 판매 상태를 직접 갱신하고 싶습니다.
- 방문자는 메뉴 페이지에서 게시된 메뉴와 가격을 확인하고, 품절 메뉴는 품절 상태로 알아볼 수 있어야 합니다.
- 공개·판매 상태를 잘못 설정하거나 삭제 데이터를 잃는 일을 줄이는 것이 목표입니다.

## 합의한 1차 범위

- `/admin/menu`에서 메뉴를 카테고리별 현재 순서로 보여줍니다. 목록에는 메뉴명, 가격, 게시 상태, 판매 상태와 수정 동작을 표시합니다. 모바일에서는 카드형으로 읽고 조작할 수 있게 합니다.
- 추가와 수정은 별도 폼에서 처리합니다. 기존 카테고리를 선택하고 메뉴명, 설명, 가격, 순서, 게시 여부와 판매 상태를 입력합니다.
- 게시 상태와 판매 상태는 구분해 표시합니다. 미게시 메뉴는 공개 페이지에서 숨기고, 품절 메뉴는 공개 페이지에서 품절로 표시합니다.
- 삭제는 확인 후 soft-delete로 처리하며, 삭제된 메뉴를 복구할 수 있습니다. 영구 삭제는 제공하지 않습니다.
- 신규 메뉴의 초기 상태는 schema 기본값에 맞춰 **공개·판매중**으로 제안합니다. 저장 즉시 방문자에게 노출될 수 있으므로 이 기본값을 폼에서 명확히 보여주고, 운영자가 저장 전에 확인해야 합니다.

## 제외 범위와 근거

- 이미지 업로드·교체: 이미지 원본 준비와 업로드 운영 방식이 정해지지 않았습니다. 기존 이미지 연결은 수정 중 보존하고, 이미지 없는 메뉴는 공개 페이지의 기존 fallback을 사용합니다.
- 카테고리 CRUD: 현재 카테고리를 선택하는 요구는 충족하되, 카테고리의 이름·slug·추가·삭제 관리는 이번 요청 범위에 없습니다.
- 검색·일괄 편집: 기본 메뉴 CRUD에 필요하지 않아 작업량과 오조작 가능성을 늘리지 않도록 제외합니다.
- 영구 삭제: 복구와 데이터 보존을 우선하며, 복구 기간과 이미지 참조 정책도 정해지지 않았습니다.

## 후속 작업

- FE/BE: 폼 입력 검증, 상태별 목록·공개 표시, soft-delete와 복구 흐름을 구현하고 저장 결과를 운영자가 확인할 수 있게 합니다.
- PD: 데스크톱 목록과 모바일 카드, 폼 위계, 버튼 크기와 삭제 확인 동작을 검수합니다.
- PM: 실제 운영자에게 메뉴 추가·가격 수정·품절 전환·삭제 후 복구를 수행하게 해 완료 시간과 오입력·복구 횟수를 확인합니다. 기준 데이터가 없어 성과는 검증 전까지 단정하지 않습니다.

## 완료 기준

- 관리자 목록이 카테고리와 공개 순서를 따르며 게시·판매·삭제 상태를 구분합니다.
- 기존 카테고리를 선택해 메뉴를 추가·수정할 수 있고, 이름·설명·가격·순서·게시·판매 상태가 저장 후 다시 표시됩니다.
- 삭제한 메뉴는 공개 목록에서 사라지고 관리자 화면에서 복구할 수 있습니다. 복구된 메뉴의 게시 상태에 따라 공개 페이지가 갱신됩니다.
- 공개 메뉴 페이지에서 게시 메뉴의 이름·설명·가격이 관리자 데이터와 일치하고, 품절 메뉴는 품절로 표시됩니다.
- 주요 조작 대상은 WCAG 2.2의 최소 target size 기준을 검토하고, 키보드로 폼과 삭제 확인을 조작할 수 있습니다. 맞춤 대화상자를 사용한다면 초점 이동과 닫은 뒤 초점 복귀를 확인합니다.

## 미결 질문

- 이미지 없는 메뉴의 공개 fallback을 운영자가 허용하는지, 이미지 업로드·교체를 후속 범위로 둘지 확인이 필요합니다.
- 카테고리 추가·이름·순서 변경이 실제 운영에서 얼마나 자주 필요한지 확인이 필요합니다.
- 삭제 확인은 브라우저 기본 확인으로 충분한지, 맞춤 대화상자가 필요한지 구현 단계에서 접근성 동작을 확인합니다.

이 문서는 1차 범위의 운영 방식과 남은 질문이 확인되면 같은 주제의 후속 회의에서 갱신합니다.
