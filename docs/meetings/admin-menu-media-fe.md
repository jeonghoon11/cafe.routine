# 관리자 메뉴 이미지·상태·순서 FE 회의록

일자: 2026-10-13
참석 역할: PM, PD, FE, BE

## 논의와 결정

- 공개와 판매 상태를 별도로 받던 폼은 판매 중·비공개 두 상태로 통합한다.
  기존 두 값이 모두 true일 때만 판매 중으로 표시한다. 공식 사이트 query와
  RLS도 두 조건을 확인한다. 기존 품절 행은 숨기며 자동으로 판매 중으로 바꾸지 않는다.
- 정렬 자동 저장과 명시 저장을 비교했다. 드래그 실수와 저장 실패를 사용자가
  구분할 수 있도록 ‘순서 편집’ 모드와 ‘순서 저장’·‘취소’를 선택했다.
  메뉴 수정 버튼과 독립적으로 순서를 바꿀 수 있다.
- 정렬 대상은 같은 카테고리의 비삭제 메뉴이며 비공개도 포함한다.
  카테고리 간 이동은 메뉴 수정 폼에서 수행하고 해당 카테고리 마지막에 붙인다.
- Pointer Events는 마우스·터치 손잡이에만 사용한다. 위로·아래로 버튼은
  키보드와 단순 클릭의 대안이며 이동 결과를 status로 안내한다.
- 순서 편집 중 추가·수정·복구를 막고 변경 후 링크 이동·로그아웃 제출·
  새로고침과 문서 이탈을 확인한다.
  저장 실패 시 초안을 유지한다. 변경 없는 저장은 막는다.
- 메뉴 이미지 선택·제거는 저장 전 미리보기이며 바로 DB에 반영하지 않는다.
  파일 선택 취소는 이전 선택을 유지한다. 제거 후 같은 파일 재선택이 가능해야 한다.
- 이미지 기준은 JPG·PNG·WebP 최대 1MiB(화면 1MB)이며 SVG·GIF·AVIF는 제외한다.
  클라이언트 decode와 서버 MIME/signature/크기 검증을 수행한다. width/height는
  표시 메타데이터로 1..16384, 총 4천만 픽셀 한도를 적용한다.
- SEED ActionButton과 semantic token, 기존 폼 구조를 사용하고 추가 라이브러리를
  설치하지 않는다. 이미지 원본·공용 참조는 제거하지 않고 메뉴 연결만 해제한다.

## 구현과 검증

- menu-list.tsx가 목록 상호작용, menu-form.tsx가 이미지 선택과 입력 유지 상태를 담당한다.
- Next Server Action 2MB, 실제 파일 1MiB 제한을 함께 적용한다.
- FE task worktree에서 pnpm typecheck, pnpm lint, git diff --check를 통과했다.
- 부모 에이전트의 별도 mock 환경 E2E 총 35개와 빌드가 통과했다.
  마우스 드래그 검증에서 행 재배치 후 capture 소실을 발견해 stable ul로 capture를 옮겼고
  실제 마우스·가상 touch 입력으로 재검증했다. 운영 메뉴·Storage 쓰기 테스트는 하지 않았다.
  부모가 사용자 승인 후 운영 migration을 적용해 SQL 성공을 확인했다.

## 한계

- 서버가 전체 이미지 decode를 수행하지 않으므로 전달한 치수가 실제 이미지와
  일치하는지까지는 검증하지 않는다. 치수는 권한·파일 접근 제어에 사용하지 않는다.
- 동시 작업은 category/row 잠금 순서에 따라 deadlock으로 한 요청이 실패할 수 있다.
  RPC는 원자 저장하며 오류 시 부분 저장하지 않고 다시 시도하도록 안내한다.

- 브라우저 뒤로가기의 같은 문서 내 App Router 이동은 beforeunload로 차단할 수 없다.
  history 조작으로 뒤로가기를 덮어쓰지 않으며 이동 전 순서 저장·취소가 필요하다.

## 드래그 모션 후속 구현

사용자 요청에 따라 잡은 행은 포인터를 따라 움직이고 주변 행은 180ms 동안 자리를 비우도록 개선했습니다. 놓을 때 새 슬롯에 정착하며, 동작 줄이기 설정에서는 슬라이드 모션을 생략합니다. 저장 계약은 동일합니다. localhost mock E2E 14개와 typecheck/lint/diffcheck를 통과했습니다.
