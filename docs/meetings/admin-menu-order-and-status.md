# 관리자 메뉴 상태와 순서 회의

## 주제와 참여

- 일자: 2026-10-13
- 참여: PM, PD, FE. BE는 저장 계약을 검토합니다.
- 사용자 요구: 판매 중인 메뉴만 공식 메뉴 페이지에 표시하고, 비공개 메뉴는 숨깁니다. 순서는 수정 폼 대신 관리 목록에서 드래그로 변경합니다.

## 확인한 사실

- 기존 UI는 공개 여부와 판매 여부를 따로 입력하며 공개된 품절 메뉴도 사이트에 표시합니다.
- 기존 수정 폼에 숫자로 입력하는 `sort_order`가 있고, 목록은 카테고리와 메뉴 순서로 정렬됩니다.
- 이번 결정은 기존 [관리자 메뉴 제품 회의](admin-menu-product-design.md)의 공개·판매 상태 분리와 [메뉴 이미지 회의](menu-image-layout.md)의 품절 노출 정책을 대체합니다.

## 결정 사항과 근거

- 메뉴 상태는 **판매 중(공개)** / **비공개** 두 가지로 표시합니다. 판매 중이면 `is_published`와 `is_available`을 모두 참으로, 비공개이면 모두 거짓으로 저장합니다.
- 기존 데이터는 두 값이 모두 참인 경우만 판매 중으로 해석합니다. 기존 품절 메뉴와 미게시 메뉴는 공식 사이트에서 숨깁니다. 기존 데이터를 일괄 변경하지 않고 이후 수정 저장에서 두 값을 맞춥니다.
- 공개 조회는 두 값이 모두 참이고 삭제되지 않은 메뉴만 대상으로 합니다. 카테고리 비공개는 별도 조건이며 관리자에게 배지와 안내를 유지합니다.
- 수정 폼의 순서 입력을 제거합니다. 일반 수정은 기존 순서를 유지하고, 신규 메뉴 또는 카테고리가 바뀐 메뉴는 대상 카테고리 마지막에 추가합니다.
- 목록에서 카테고리별 **순서 편집**에 진입해 드래그하거나 위·아래 이동 버튼으로 순서를 바꿉니다. 비공개를 포함한 미삭제 메뉴만 대상으로 하며 삭제 메뉴는 제외합니다. 카테고리 사이 드래그 이동은 제공하지 않습니다.
- **순서 저장**을 눌러야 공식 사이트에 반영합니다. **변경 취소**는 편집 시작 시 순서로 돌아갑니다. 메뉴 수정 버튼을 누르지 않고도 순서를 저장할 수 있습니다. 반복 드래그가 운영 화면에 즉시 반영되는 실수를 줄이는 것이 이유입니다.
- 편집 중에는 메뉴 추가·수정·복구 동작을 막고 먼저 저장하거나 취소하도록 안내합니다. 변경된 상태에서 화면을 떠날 때는 미저장 변경을 알립니다.
- 저장 중에는 중복 저장과 추가 이동을 막습니다. 실패하면 편집한 순서를 유지하며 재시도할 수 있게 하고, 성공한 경우에만 저장 완료를 안내합니다.
- 다른 작업으로 메뉴 구성이나 순서가 달라졌다면 저장을 거부하고 새로고침을 안내합니다. 일부 순서만 저장되는 상태를 방지하기 위한 원자 저장과 비교 방식은 BE가 계약을 검토합니다.

## 문구

- 상태 도움말: “판매 중인 메뉴만 공식 사이트에 표시됩니다.”
- 순서 편집 안내: “저장 전에는 사이트에 반영되지 않습니다.”
- 저장 완료: “메뉴 순서를 저장했습니다.”
- 동시 변경: “다른 변경이 있습니다. 새로고침한 뒤 다시 정렬해 주세요.”

## 담당자별 후속 작업

- FE: 두 상태 폼과 목록, 순서 편집·드래그·위아래 이동·저장·취소, 실패 피드백, 공개 조회 조건을 구현합니다.
- BE: 관리자 권한 검증, 정렬 저장의 입력·멤버십·동시 변경 검사, 원자 저장 계약을 검토합니다.
- PD: 모바일과 키보드 조작, 편집 중 잠금, 저장 전후 안내를 검토합니다.
- PM: 최신 사용자 요구와 상태 해석, 실수·실패·이탈 케이스 및 완료 기준을 확인합니다.

## 완료 기준과 검증 상태

- 판매 중만 사이트에 보이고 비공개·기존 품절·삭제 메뉴는 보이지 않습니다.
- 수정 화면에 순서 입력이 없고 일반 수정으로 순서가 바뀌지 않습니다.
- 목록에서 드래그 및 위·아래 버튼으로 순서를 변경할 수 있고 저장 전에는 사이트 순서가 유지됩니다.
- 취소 시 초기 순서로 복원되고 저장 성공 후 새로고침해도 순서가 유지됩니다.
- 정렬 실패·동시 변경·비관리자 요청은 성공으로 표시되지 않으며 부분 반영되지 않습니다.
- 390px 모바일, 키보드 조작, 미저장 안내와 편집 중 잠금을 로컬 가상 E2E로 확인합니다.
- 구현 완료. 로컬 mock E2E에서 상태 필터, 순서 취소·실패·재시도·stale 거부, 실제 마우스·가상 터치·키보드 조작, 링크·로그아웃 이탈 확인을 통과했습니다. 이미지 흐름 포함 총 35개 검증이며 `pnpm typecheck`, `pnpm lint`, `pnpm build`, `git diff --check`를 통과했습니다. 운영 메뉴 쓰기 테스트는 수행하지 않았습니다.

## 미결 사항

- BE 리뷰 후 `reorder_menu_items` RPC가 전체 ID·sort_order·updated_at 스냅샷을 비교하고 트랜잭션으로 저장하도록 구현했습니다.
- 사용자 승인 후 운영 migration 실행 성공을 확인했습니다. 운영 검증은 카탈로그 조회로 정책·함수·트리거 확인만 수행하며 실제 메뉴 쓰기는 하지 않습니다.

## 운영 반영 확인

사용자 승인 후 migration 실행 성공을 확인했습니다. 읽기 전용 조회로 공개 정책의 AND 조건, 순서 RPC 등록·트리거 활성, 익명 실행 차단과 인증 사용자 실행 권한을 확인했습니다. 메뉴·Storage 쓰기 검증은 가상 환경에서만 수행했습니다.
