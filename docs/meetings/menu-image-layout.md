# 메뉴 이미지·레이아웃 회의

## 주제

Supabase 메뉴 이미지 연결과 공개 메뉴 페이지의 이미지 중심 레이아웃 개선

## 참여 직군

BE, FE, PD, PM

## 사용자 문제와 목표

- 방문자는 메뉴명과 가격만으로는 메뉴를 비교하기 어려우므로, 실제 메뉴 이미지와 설명을 함께 확인할 수 있어야 합니다.
- 모바일에서도 이미지 때문에 메뉴명, 설명과 가격을 놓치지 않고 빠르게 비교할 수 있어야 합니다.
- 메뉴 선택 후 기존 방문 정보 동선으로 자연스럽게 이동할 수 있어야 합니다.
- 이미지와 메뉴 연결은 확인된 자료만 사용해 잘못된 메뉴 사진이 노출되지 않게 합니다.

## 결정 사항과 근거

- 데스크톱은 카테고리별 2열, `4:3` 이미지 카드로 구성합니다. 사진을 충분히 보여주면서도 메뉴 비교 밀도를 유지하기 위한 선택입니다.
- 모바일은 `112x112` 썸네일을 둔 가로 카드로 구성합니다. 제한된 화면에서 이미지와 메뉴 정보를 함께 읽기 위한 선택입니다.
- 카드 정보 위계는 `메뉴명 → 설명 → 가격`으로 통일합니다. 선택에 필요한 핵심 정보를 예측 가능한 순서로 제공합니다.
- 기존 sticky category navigation과 hash 이동은 유지합니다. 현재 탐색 동선을 보존하고 변경 범위를 줄입니다.
- active category scrollspy는 이번 범위에서 제외합니다. 메뉴 이미지 제공이라는 핵심 목표에 필요하지 않은 별도 상태 관리를 추가하지 않습니다.
- 이미지는 Supabase `media_assets`의 `alt`, `width`, `height`를 사용합니다. 접근 가능한 대체 정보와 안정적인 레이아웃을 제공하기 위한 기준입니다.
- 이미지가 없으면 ROUTINE fallback을 표시합니다. 확인되지 않은 다른 사진을 대신 연결하지 않습니다.
- `is_available=false`인 메뉴는 숨기지 않고 품절 문구와 낮춘 명도로 표시합니다. 메뉴 존재는 알리되 현재 주문할 수 없음을 분명히 전달합니다.
- hover와 `focus-visible` 상태를 함께 제공하고, 빈 카테고리·전체 메뉴 없음·긴 메뉴명에서도 정보 구조가 깨지지 않게 합니다.
- 새 추천·인기순·리뷰 기능은 근거 데이터와 운영 정책이 없어 추가하지 않습니다.

## 담당자별 후속 작업

- BE
  - 제공된 매장 사진과 확인 가능한 네이버 메뉴 사진을 Supabase Storage와 `media_assets`에 저장했습니다.
  - 확인된 메뉴만 `menu_items.media_id`와 1:1로 연결하고, 매칭할 수 없는 메뉴는 fallback으로 남겼습니다.
- FE
  - 합의한 반응형 카드 레이아웃과 정보 위계, 품절·fallback·empty state를 구현했습니다.
  - sticky category navigation과 hash 이동, 기존 방문 정보 이동 경로를 유지했습니다.
  - 데스크톱과 모바일에서 이미지 로딩, fallback과 가로 overflow를 검증했습니다.
- PD
  - 데스크톱과 모바일의 이미지 비율, 카드 밀도, 텍스트 대비와 시선 흐름을 검수했습니다.
  - hover, `focus-visible`, 품절 명도와 fallback이 접근성과 브랜드 방향을 유지하는지 확인했습니다.
- PM
  - 메뉴명·설명·가격·품절 상태가 공식 자료와 일치하는지 운영자 확인 항목을 관리합니다.
  - 배포 후 메뉴 탐색에서 방문 정보 이동까지의 이탈과 행동을 측정할 수 있는지 검토하되, 분석 도구가 확정되기 전 성과를 단정하지 않습니다.

## 구현·검증 결과

- Supabase `site-assets`에 매장 공간 사진 4개와 메뉴 사진 14개를 WebP로 업로드했습니다.
- `media_assets` 18행을 등록하고, 확인된 메뉴 14개의 `menu_items.media_id`를 정확히 연결했습니다.
- 모든 public URL이 HTTP 200과 `image/webp`로 응답했으며 기존 자산 삭제나 덮어쓰기는 없었습니다.
- 네이버 현재 목록에서 확인할 수 없는 `ADE`, `COLD BREW`, `CREAM CHOCOLATE`, `CREAM MATCHA`, `FLOWER TEA`, `ICE TEA` 6개는 잘못 매칭하지 않고 ROUTINE fallback을 유지했습니다.
- 네이버에만 있는 밀크티는 DB 메뉴에 없으므로 새 메뉴로 만들지 않았습니다.
- 공개 메뉴 UI는 데스크톱 2열 `4:3` 카드와 모바일 `112x112` 가로 카드로 구현했습니다.
- 실제 브라우저에서 이미지 14개 로딩, fallback 6개, 가로 overflow 0을 확인했습니다.

## 완료 기준

- 확인된 각 메뉴 이미지는 Supabase Storage와 `media_assets`에 등록되고 올바른 `menu_items.media_id`에 연결됩니다.
- 확인할 수 없는 이미지는 잘못 연결되지 않으며 ROUTINE fallback으로 표시됩니다.
- 데스크톱은 카테고리별 2열 `4:3` 카드, 모바일은 `112x112` 가로 카드로 표시됩니다.
- 모든 카드에서 메뉴명, 설명, 가격과 품절 상태를 구분해 읽을 수 있습니다.
- 이미지 크기로 인한 layout shift를 줄이고 의미 있는 `alt`를 제공합니다.
- sticky category navigation, hash 이동과 기존 방문 정보 동선이 유지됩니다.
- 이미지 없음, 빈 카테고리, 전체 메뉴 없음, 긴 메뉴명, hover, 키보드 focus를 검증합니다.

## 미결 질문

- fallback 상태인 6개 메뉴의 공식 이미지를 누가 확보하고 등록할 것인가?
- 메뉴 설명과 품절 상태를 Cafe Routine 관리자 페이지에서 누가 어떤 주기로 갱신할 것인가?

이 문서는 미결 운영 책임과 추가 공식 이미지가 확정되면 같은 주제의 후속 회의에서 갱신합니다.
